Team Delivery Pipeline · v2 · for server applications

Five roles, three gates

A robust pipeline for building a server application (backend + client, deployed online). The Product Manager hands raw prompts; the Coordinator turns them into the final PRD and drives the team through design → tech → build → QA → publish — stopping at three human gates where the PM must approve before work continues.

target server application (real backend + deploy) docs all HTML, committed to the repo gates 3 human approvals

4Operating rules

How the pipeline runs

  • Three hard human gates. Between gates the team runs autonomously; at each gate, all work stops until the PM approves.
  • PM gives prompts; Coordinator authors the PRD. The PM doesn't write the final spec — raw intent in, polished PRD out.
  • One merged Tech Document. Infrastructure design, frontend, backend, and the QA test plan land in a single doc for Gate 2.
  • Green before advancing. Build doesn't progress past QA until the Test Report is clean.
  • HTML, in the repo. Every working document is self-contained HTML, committed as produced — a complete record.
  • Server target. "Build the servers" and "publish online" are literal: a real backend, deployed, with the client talking to it.
