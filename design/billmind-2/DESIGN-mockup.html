The two-layer scroll

  • Ledger = permanent, synced, day-grouped bills
  • Conversation = ephemeral working layer (capture + answers)
  • Confirm → the bill docks up into the ledger, total counts up
  • Conversation is per-trip; switching trips swaps the whole surface

"Computed, not guessed"

  • Every number lives in a tool-result chip with a "computed" mark
  • Tap a chip → the exact bills it summed (provenance = trust)
  • In this mockup the answers really sum the ledger — try adding a bill, then "how much on food?"
  • If a number isn't in a chip, it's a bug (a QA test point)

One input, two jobs

  • The agent routes intent: number → capture; question → answer
  • Ambiguous → two chips, never a silent bill on money
  • No mode toggle (that re-introduces the tab-hop the merge kills)
  • Read = instant · write = always confirmed
